# Қазақ хандығы: Хан тағы · GAME HUB CYB26-03

Қазақстан тарихына негізделген браузерлік ойын (2-техтапсырма, **Strategy + Tower Defense**) және оның ойын порталы (GAME HUB).

**Сайт:** https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/ *(орнатқаннан кейін ауыстырыңыз)*
**Команда:** [аты-жөндеріңіз]

## Ойын туралы

Әр кезеңде үш қадам:
1. **Кеңес** (Reigns сияқты): тарихи тұлға мәселе әкеледі, карточканы оңға/солға сырғытып шешім қабылдайсыз. 4 көрсеткіш өзгереді: 👥 Халық бірлігі, ⚔️ Әскер қуаты, 💰 Қазына, 📜 Бедел. Көрсеткіш 0-ге түссе — дағдарыс, −1 жан.
2. **«Тарихи шешім»** — маңызды шешімнен кейін (кезеңде 3 рет) тарихи тапсырма: дұрыс → ресурс +20, қате → әскер −10%.
3. **Қорғаныс** (Tower Defense): Қазақстан картасында әскер (садақшы, найзагер, манжаниқ) орналастырасыз, қалаларды дамытасыз, елші жібересіз (дипломатия), ханның қабілетін қолданасыз. Жау ордаға жетсе — −1 жан.

Жан біткенде — «Медициналық көмек»: тарихи тапсырма, дұрыс → +1 жан (кезеңде 2 рет). 10 хан (Керей, Жәнібек, Қасым, Хақназар, Тәуекел, Есім, Жәңгір, Тәуке, Абылай, Кенесары), 10 кезең (1465 → Кенесары қозғалысы, 10-кезең BOSS), 100 сұрақ, 6 тапсырма түрі (бір жауап, сәйкестендіру, хронология, карта, сурет/артефакт, бос орын).

## Архитектура

```
Браузер (HTML5 Canvas, JavaScript)
   │  publishable key + қолданушы JWT, тек HTTPS
   ▼
Supabase Auth (Google OAuth 2.0, PKCE)     Supabase Edge Functions
                                              khan-start  — кезең бастау, сұрақтарды ЖАУАПСЫЗ беру
                                              khan-answer — жауапты серверде тексеру
                                              khan-finish — ұпайды серверде есептеу, рейтинг
                                              admin-panel — құпиясөзбен кіретін админ, Excel, тазалау
                                                 │ secret key (тек серверде)
                                                 ▼
                                 PostgreSQL + Row Level Security
                                 profiles · leaderboard · khan_questions · khan_games · khan_answers · admin_log
GitHub → GitHub Pages (HTTPS)
```

## Киберқауіпсіздік
- Google OAuth 2.0 (PKCE), сессияны Supabase Auth басқарады.
- Дұрыс жауаптар браузерге жіберілмейді; жауапты да, ұпайды да сервер есептейді.
- Row Level Security: әр студент тек өз деректерін оқиды, рейтингке тек сервер жазады.
- Клиент жіберген сандарды сервер шектейді (жеңілген жау ≤ кезеңдегі жау саны, жан, көрсеткіштер 0–100), кезеңді тым жылдам аяқтау қабылданбайды, кезеңдер ретімен ашылады.
- Rate limiting: 15 секундта бір ойын, минутына 30 жауап, админ құпиясөзі — 15 минутта 5 қате.
- Input validation (ат: 2–30 таңба), XSS-тен қорғау (тек textContent, CSP), secret key мен құпиясөздер тек Supabase Secrets-те.

# Установка (для команды, ~40 минут)

Нужны: аккаунт GitHub, аккаунт Supabase (можно войти через GitHub или email), Google-аккаунт для Google Cloud.

**Никогда не публикуйте и не присылайте никому:** пароль базы данных Supabase, Secret key (`sb_secret_…`), Google Client secret, `ADMIN_PASSWORD`. Publishable key (`sb_publishable_…`) — не секрет, его можно держать в `config.js`.

### 1. GitHub
1. Создайте новый **публичный** репозиторий (например, `khan-tagy`).
2. **Add file → Upload files** → перетащите всё содержимое архива (файлы и папки, не саму внешнюю папку) → **Commit changes**.
3. **Settings → Pages** → Source: *Deploy from a branch*, Branch: `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты сайт будет по адресу `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`. Запишите его.

### 2. Supabase — проект и база
1. **New project** → придумайте пароль БД (сохраните у себя) → регион любой → Create.
2. **SQL Editor → New query** → вставьте весь файл `supabase/schema.sql` → **Run**. Должно быть «Success. No rows returned».

### 3. Google Cloud — вход через Google
1. https://console.cloud.google.com → создайте проект.
2. **APIs & Services → OAuth consent screen**: тип *External*, имя приложения, email поддержки. В **Branding** укажите Home page = адрес сайта, Privacy policy = `адрес сайта/privacy.html`.
3. **Clients → Create client → Web application**:
   - Authorized JavaScript origins: `https://ЛОГИН.github.io`
   - Authorized redirect URIs: `https://ВАШ-ПРОЕКТ.supabase.co/auth/v1/callback` (точный адрес есть в Supabase → Authentication → Sign In / Providers → Google → *Callback URL*).
   - Скопируйте **Client ID** и **Client secret**.
4. **Audience → Publish app**, чтобы мог войти любой студент, а не только тестовые пользователи.

### 4. Supabase — Google и адреса
1. **Authentication → Sign In / Providers → Google** → Enable → вставьте Client ID и Client secret → Save.
2. **Authentication → URL Configuration**: Site URL = адрес сайта (без пробелов!), в Redirect URLs добавьте тот же адрес.

### 5. Supabase — секреты и функции
1. **Edge Functions → Secrets** → добавьте:
   - `SITE_ORIGIN` = `https://ЛОГИН.github.io` (без `/` в конце и без названия репозитория)
   - `ADMIN_PASSWORD` = пароль для админ-панели (минимум 8 символов)
2. **Edge Functions → Deploy a new function → Via Editor** — четыре раза, имена строго такие: `khan-start`, `khan-answer`, `khan-finish`, `admin-panel`. В каждую вставьте код из `supabase/functions/ИМЯ/index.ts` → Deploy.
3. В каждой функции: **Details → Verify JWT** — выключить (функции сами проверяют пользователя).

### 6. Подключить сайт к Supabase
1. В Supabase: **Project Settings → Data API** — скопируйте Project URL; **API Keys** — скопируйте Publishable key.
2. На GitHub откройте `assets/config.js` → ✏️ → замените две строки на свои значения → Commit.
3. Подождите 1–2 минуты, откройте сайт, обновите с **Ctrl+F5**, войдите через Google.

### 7. Проверка
- «Ойындар тізімі» → «Хан тағы» → «Ойнау» → пройдите 1-кезең.
- «Рейтинг» и «Нәтижелер» показывают результат.
- «Админ баптаулары» → пароль из `ADMIN_PASSWORD` → Excel.
- (Необязательно) сделать себя админом, чтобы все 10 этапов были открыты для демонстрации: SQL Editor → `update profiles set is_admin = true where email = 'ваш@gmail.com';`

**Если что-то не работает:** ошибка входа 500 — проверьте Site URL (лишний пробел) и логи в Authentication → Logs; «Сервермен байланыс қатесі» — функция не задеплоена, неверное имя, включён Verify JWT или не задан `SITE_ORIGIN`; «Админ құпиясөзі орнатылмаған» — нет секрета `ADMIN_PASSWORD`.
